## 1. Where this fits in the course

Block 1's objective is to build formal tools for decision making before Managerial Economics turns to pricing and market structure. Class 1 opens with the master framework used all block: **decision trees**. The pitch on slide 3 ("Thinking like an Economist") is the thesis of the whole course:
- Carefully compare **costs and benefits**, evaluated **at the margin**, not on average.
- **Strategic actors** drive the data you observe (beware naively fitting models/ML to data generated by other rational agents).
- **Incentives matter** — you get what you pay for.
- Caveats: economics doesn't tell you *what* goal to pursue (only how to achieve a given goal); it doesn't resolve interpersonal tradeoffs ("should I help Alice at Bob's expense?") — it just *uncovers* the tradeoff; and it can't substitute for judgment ("ignore your gut at your own peril").

**Methodology** (slide 5): identify a decision problem → strip it down to a tractable "toy model" → beware "garbage in, garbage out" (Box: "all models are wrong, some models are useful") → think hard about assumptions and run sensitivity analysis → use cases/articles to practice.

## 2. The Fundamental Trio

Every decision problem (Hermalin §1.1, lecture slide 17) has three components:
1. **Actions** — what are my alternatives?
2. **Outcomes** — what results from my choice? (Often uncertain.)
3. **Objectives** — what outcomes are desirable? For firms: expected profit maximization. For individuals: expected "utility" maximization (a useful benchmark even though it sounds cold — "what I really need in order to feel fulfilled is ___").

Hermalin's opening story (a former student deciding whether to flee Hurricane Andrew or stay) makes the point that decision theory doesn't replace judgment — it **formalizes** it: it surfaces your alternatives, tells you what information would help, and forces you to state the assumptions your decision rests on.

## 3. Decision trees under certainty

A **decision tree** represents a decision problem as branching alternatives read left to right. **Decision nodes** are squares (the decision maker chooses a branch); the branches at the far right end in **payoffs**.

**Hermalin's canonical example (Fig. 1.1, p. 4):** A firm choosing whether to run a marketing campaign ($1M cost) and then whether to produce. If marketed & produced: revenue $8M − $2M production − $1M campaign = **$5M** profit. If marketed, not produced: **−$1M** (campaign cost only). If not marketed, produced: $4M revenue − $1M production = **$3M**. If neither: **$0**.

**Solving a tree = backward induction.** Start at the *rightmost* decision nodes and pick the branch with the highest payoff; "value" that node with the payoff; then move one step left and repeat, now treating the values you just computed as the payoffs. In Hermalin's example: at the top-right node, "produce" ($5M) beats "don't produce" (−$1M), so the node is valued at $5M; at the bottom-right node, "produce" ($3M) beats "don't" ($0), valued at $3M. Moving left, "marketing campaign" ($5M) beats "no campaign" ($3M) — the firm should run the campaign.

The lecture's own version of this (slide 19–20) uses a breakfast example (Cold: Cheerios=3 / granola=4; Hot: bacon&eggs=−2 / pancakes=5; Nothing=−10) to make the same point: **decisions are irreversible**, so you must look forward and solve backward.

## 4. Decision trees under uncertainty

Uncertainty is represented by a **chance node** (circle): each branch from it is a possible state of nature, with probabilities that must sum to 1.

**Hermalin's launch example (Fig. 1.3, p. 6):** A firm can launch (chance node: blockbuster $7M [.55], acceptable $3M [.40], failure −$4M [.05]) or not launch ($0). Expected value of launching:
```
EV = .55×$7M + .40×$3M + .05×(−$4M) = $3.85M + $1.2M − $0.2M = $4.85M
```
Launch beats not-launching ($0).

**The lecture's running example — "Get an MBA?" (slides 22–24):** value of an MBA depends on whether the job market is strong or weak.
```
Strong market: benefit 20 − cost 10 = 10
Weak market:   benefit  5 − cost 10 = −5
```
With P(strong) = p, the expected value of getting an MBA is
```
v = 10p + (−5)(1 − p) = 15p − 5
```
**Get the MBA iff 15p − 5 > 0, i.e., p > 1/3.** Below p = 1/3 the expected loss from a weak market outweighs the expected gain from a strong one; above it, get the MBA. This is the same "solve for the threshold parameter" trick used throughout the course. **Crucial caveat (slide 24, in red):** *don't confuse bad/good decisions with bad/good outcomes* — a rational decision made with p > 1/3 that happens to land in the weak-market branch was still the *correct* decision ex ante.

**Refining the tree with a two-stage lottery (slides 27–28):** Suppose the *true* p = 1/2, but it's driven by an underlying inflation state: if inflation falls (prob .5), P(strong | inflation falls) = 0.9; if inflation stays high (prob .5), P(strong | inflation high) = 0.1. This nested tree has the same unconditional p = 0.5×0.9 + 0.5×0.1 = 0.5, and the *unconditional* expected value is identical (V = 2.5) to the simple one-shot tree — "effectively the same tree" — **unless** the decision maker gets to observe the inflation state before deciding. That distinction is exactly what launches the Information section.

## 5. The Value of Information

**Setup (slides 27–30):** If you could learn *whether inflation will rise* before deciding on the MBA, your decision becomes **contingent** on that information:
- If inflation falls: conditional value of MBA = 10(.9) + (−5)(.1) = **8.5** > 0 → get MBA.
- If inflation stays high: conditional value of MBA = 10(.1) + (−5)(.9) = **−3.5** < 0 → don't get MBA (fall back to the $0 "stay" branch).

Expected value **with** this information = 0.5×8.5 + 0.5×0 = **4.25**. Expected value **without** it (from §4) = **2.5**.
```
Added value of information = value_with − value_without = 4.25 − 2.5 = 1.75
```
That $1.75 (in the same units as the payoffs) is your **willingness to pay** for the inflation forecast.

**The Three Rules of Information (slide 30, lecture's own phrasing):**
1. *First rule:* Information that cannot affect your decision is worthless; otherwise it is valuable.
2. *Second rule:* Information is most valuable when you are clueless.
3. *Third rule:* Information is most valuable when, without it, you are close to indifferent between alternatives.

These three rules are exactly Hermalin's three formal results (Ch. 1.4, pp. 9–17), independently derived through a richer worked example (a firm deciding whether to accept, return, or test-run a shipment of sheet metal that might be high- or low-quality):

> **Result 1 (Fundamental Rule of Information).** *Information has value only if it has the potential to affect a decision maker's choice of action.*

Hermalin shows this with a threshold: if the test run's informativeness parameter p ≤ 5/6, the firm would produce regardless of the test result — information has *no* potential to change the action, so it's worthless. If p > 5/6, the result *can* flip the decision (don't produce if the test says "likely not okay") — so the information becomes valuable, worth exactly `p×$3M − $1.5M` (for p > 5/6).

> **Result 2.** *Perfect information is always at least as valuable as imperfect information.*

> **Result 3.** *The value of information is maximized when the decision maker would, absent the information, view alternative actions as equally attractive* — i.e., value is highest exactly at the point of indifference (Hermalin's Figure 1.8 shows value of information peaking at $1M when z = $1M, precisely the value that makes the firm indifferent between producing and returning the metal with no information).

**Takeaway:** the value of any survey, forecast, pilot test, or "wait and see" strategy is *always* the gap between the best achievable expected value with contingent decisions and the best expected value without them — never more, never less.

## 6. Real Options (brief — Hermalin §1.5, pp. 18–19)

A **real option** is the ability to delay an irreversible commitment until some uncertainty resolves through the mere passage of time (distinguished from *financial* options only by context). Hermalin's delay example: a firm can launch now (EV = $4M across high/moderate/low-growth outcomes) or delay and learn the state of the economy first (EV = $6M − (3/5)D, where D ≥ 0 is the cost of delay). **Delay is worthwhile iff $6M − (3/5)D ≥ $4M, i.e., D ≤ $3⅓M.**

The key conceptual distinction from a survey: the cost of ex-ante information (a forecast) is *always* borne, even if you end up not launching; the cost of delay is borne only *if you would have wanted to act anyway* — so decision makers should tolerate a *higher* cost for delay than for the equivalent amount of information purchased upfront. This idea — real options via delay — is exactly what Class 2's Merck "wait for Version B" decision and the airline fuel-hedging example both build on.

## 7. Setting up an inventory/standing-order decision (preview of the Fenmark case)

The lecture pivots (slides 9–12) into the **Fenmark Case**, using it as the vehicle for practicing "what's the objective, and what are the actions/outcomes." Two restaurants sell fish at price p = $15, cost c = $6 per fish, with different standing orders X (400 vs. 420). Let D = daily demand (random) and S = actual sales = min(D, X). Then:
```
Profits = (p)×S − (c)×X = 15S − 6X
```
Written piecewise (splitting on whether demand exceeds the standing order):
```
Profits = { 9D − 6(X − D)   if X ≥ D   (profit margin on sales, minus cost of wasted/unsold fish)
          { 9D − 9(D − X)   if X ≤ D   (profit margin on sales, minus opportunity cost of demand turned away)
```
The two terms being subtracted are explicitly labeled on the slide as the **opportunity cost of waste** (ordering too much) and the **opportunity cost of lost demand** (ordering too little) — this is the same opportunity-cost logic that gets formalized in Hermalin Ch. 3 and picked up fully in Class 2. The case's central tension (worked with real data in the companion Case Studies notes) is that the manager who orders more (and so wastes more fish on average) isn't necessarily *worse* — she may simply be facing a more volatile demand distribution, and the marginal calculus above may already be roughly optimized for her restaurant.

## Cross-cutting themes / Punchline

1. **Decision trees are a discipline, not a formula.** Their real value (per the lecture's own framing) is forcing you to name your alternatives, your assumptions about probabilities and payoffs, and to *notice* when you're conflating a bad outcome with a bad decision.
2. **Information and real options are the same idea in different clothes**: both convert a single unconditional choice into a set of *contingent* choices, and their value is always measured as the gap between the best contingent-strategy payoff and the best single-choice payoff. Information (survey, forecast) is paid for regardless of the outcome; delay (a real option) is only "paid for" via the foregone value of committing early, and only when you would have wanted to act anyway.
3. **Opportunity cost is already lurking in Class 1**, in the Fenmark profit formula's two branches (waste vs. lost demand) — this is the seed for all of Class 2 and 3's cost theory.
